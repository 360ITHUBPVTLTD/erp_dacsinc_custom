Sales Order · Raw Material · Subcontract · Embroidery · Delivery

One set of rules, the same on every screen

If the Sales Order says something is not allowed, the Purchase Order, Material Request and Sales Tracker screens don't allow it either, and they all show the same numbers in the same words. This page explains the flow, the rules, what each screen shows, and how to test it.

01The flow

Every order moves through the same steps. Items with a BOM are made by a jobber; plain (trade) items are bought as they are.

1 · Sales OrderApproved order. Each line shows what is still to make or buy.
2 · RequestShort raw material → Request RM. Short trade item → Raise MR.
3 · BuyMaterial Request → Purchase Order → Purchase Receipt. The RM is now reserved for this order.
4 · SubcontractSubcontract PO → SCO + RM sent to the jobber → Subcontracting Receipt (finished goods in).
5 · PickPick List (draft → submitted). Optional: send draft-picked qty for embroidery.
6 · DispatchDelivery Note draft = To Be Dispatched (Draft); submitted = Dispatched.
7 · DeliverSales Invoice from that DN: draft = Delivered (Draft); submitted = Delivered, then Completed.

There is one route only. A Sales Invoice with Update Stock is not used for Sales Orders (it is refused), so goods always go out on a Delivery Note and the invoice is made from that Delivery Note. "Needs Invoice" appears only when some delivered qty has no invoice yet.

02The rules

Rule 1 — Only this order's own raw material counts

An order may use its own reserved raw material (bought against it) plus unclaimed stock. Stock reserved for another order, and stock on any Pick List (draft or submitted), is on the shelf but not usable. If there isn't enough, the answer is Request RM. No screen offers a "use it anyway" option.

This applies to the SO RM table, the Sales Tracker's Create Subcontract PO, the PO form's Fetch Pending Sales Orders and Create SCO & Material Transfer dialogs, and any "Send to Subcontractor" Stock Entry, including ERPNext's own Transfer button and one typed by hand.

Rule 2 — Picked stock is for delivery only

Once a Pick List (draft or submitted) holds stock, that stock can't be sent to a jobber as raw material. To use it, reduce or cancel the Pick List first.

Rule 3 — Send to Embroidery takes draft Pick List qty only

  • Only qty on a draft Pick List of this order can be sent. Free stock that nobody has picked can't be sent: create a Pick List first.
  • A submitted Pick List can be brought back to draft with Revert to Draft — on the Pick List itself, in the Sales Order's Pick Lists, in the tracker's Pick Lists tab, or in the Send to Embroidery dialog — and then sent. Once a Delivery Note is made from it the button is gone and it says "On DN-… — can't revert".
  • While goods are at the jobber the Pick List shows a big purple AT JOBBER label everywhere and has no Submit button.
  • Once a Delivery Note (draft or submitted) is made from that Pick List, or any of it is delivered, it can't be sent.
  • You tick the items you want to send. Nothing is ticked by default.
  • While goods are at the jobber, that draft Pick List can't be submitted or deleted, and its qty can't be cut below what is at the jobber.
  • Every trip stays on record. The Pick List (form, Pick Lists modal, tracker tab) and the Send to Embroidery row show a flag: Embroidery: sent 5 · back 3 · 2 at jobber while goods are out, then Embroidery: sent 5 · all back, with one line per EWO (sent → back). On the Sales Order's Item Stock & Action Plan row the flag is clickable: it opens the history, and a trip still out has Receive right there. The row's Incoming → View dialog lists every trip too, finished ones included, with Receive, Print and Print All.

05How to test

Use two dummy orders for the same BOM item, e.g. A and B (SAL-ORD-2026-00146 / 00147 style). Buy the raw material against A only (Request RM on A → MR → PO → Purchase Receipt).

  1. Open B's RM table.Expect: Reserved for Other Order, "+60 on shelf reserved for A (not usable)", orange Request RM (60).
  2. Open A's RM table.Expect: In Stock, header "All RM in stock — ready for Subcontract PO".
  3. Sales Tracker, both rows.Expect: B "Waiting for Raw Material → Request RM"; A "RM Ready — Make Subcontract PO" with Create Subcontract PO (qty).
  4. New subcontracted PO → Fetch Pending Sales Orders.Expect: B's row disabled with "RM Reserved for Other Order — Request RM"; A's row selectable.
  5. Sales Tracker → A → Create Subcontract PO with qty + 1.Expect: refused, "own raw material covers only …". With the exact qty: the PO draft opens.
  6. Submit that PO → Create SCO & Material Transfer, type more than "Available for this PO".Expect: red "Reserved for another order — cannot send" (or "no more on the shelf"). With the exact qty: SCO + transfer are created.
  7. From the SCO, try ERPNext's Transfer Material for extra RM.Expect: the Stock Entry refuses on submit.
  8. PO → Fetch Raw Materials from SO; compare with A's and B's RM tables.Expect: identical To Make and In Stock figures.
  9. Material Request → Procurement Planner → Consolidated BOM Components.Expect: A not listed (its RM is at the jobber); B asks for its full need.
  10. Tracker → B → Request.Expect: the prompt lists Fabric blue 60 and fabric red 30 (plus a choice step if B also has trade items). Create → one draft MR.
  11. Embroidery: on an order with free stock but no Pick List, open Send to Embroidery.Expect: Can Send "—", "No draft Pick List — create a Pick List first".
  12. Create a draft Pick List, reopen, tick one item, send part.Expect: EWO created; that Pick List can't be submitted, deleted, or cut below the sent qty.
  13. Submit a Pick List, reopen Send to Embroidery.Expect: "is submitted — Revert to Draft". Reverting creates a new draft that can be sent.
  14. Receive part of it back (Job Work / Embroidery - FP), then the rest.Expect: the Pick List flag goes from "sent 5 · back 3 · 2 at jobber" to "sent 5 · all back"; the history line stays; the Pick List can be submitted again.
  15. Make a Delivery Note from a submitted Pick List.Expect: "on Delivery Note … cannot send"; revert refused.
  16. Deliver one line of a multi-line order and invoice it in full.Expect: no "Needs Invoice" / "Create Sales Invoice"; Delivery shows "Delivered n%".
  17. Try a Sales Invoice with Update Stock ticked for a Sales Order.Expect: refused, "use a Delivery Note".
  18. Delivery column: save a DN, submit it, then make the invoice.Expect: To Be Dispatched (Draft) → ✓ Dispatched → Delivered (Draft) (invoice saved) → ✓ Delivered.

Automated check — 25 Sep 2026

The same scenarios were run on this site against fresh test orders, inside a transaction that was rolled back afterwards (nothing was saved): 41 of 41 checks passed, plus an 11-step order lifecycle (New Order → MR → PO → Pick List → DN draft → Dispatched → SI draft → part-invoiced → Completed) with every Current Stage and Action Required correct. The PO prompt, the MR planner and the SO RM table showed zero differences on SAL-ORD-2026-00146 and the two test orders. Delivery chip labels were checked for all eight states.
